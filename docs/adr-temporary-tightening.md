# ADR：附加型临时收紧（P6）

- 状态：**进程内实现草案，pending-human-review；未启用自动发布**。
- 本轮范围：**不做临时收紧持久化/真实宿主原子切换**；保留离线实现与测试。
- 范围：`activation/tighten.ts` 的已批准模板、TTL/配额、双投影 epoch。
- 关联：LIFE-01–03、INJ-05、RULE-14、AC-15；PRD §5.5。

## 1. 允许什么

仅允许受信发布器按**人预先批准的模板**追加一条非 0 层、确定性的既有规则
（`deny`/`confirm`），作为项目当前激活集的附加限制。模板固定 ruleRef、
规则记录 digest、最大 TTL、窗口内最大应用次数；调用方只传模板 id 与
TTL，不能传自由文本规则或叙事。

编译使用现有 catalog v2 编译器：在 `base.project` 上增加 ruleRef、
`epoch + 1`、新的 projectConfigVersion/baseVersion，同时重编译
enforcement 与 advisory 双投影；两边共享同一 epoch/activationDigest。

## 2. 明确拒绝

- 未批准模板、未知 ruleRef、规则 digest 不匹配。
- 0 层规则、advisory_only、`on_hit` 为 `log`/`allow` 的“放宽”。
- 新增叙事、修改任何既有规则、改变 mandatory 集、改变路由/预算。
- 已激活规则、超 TTL/配额、时钟倒退。
- 无法证明“只附加”的任意语义包含关系：不尝试证明，直接拒绝。

`owner`、理由文案、模型评分都不是授权；Agent 不能发布。放宽、删除、
续期、永久化归人治理，不属于本模块。

## 3. TTL 与配额

- TTL 从受信 `apply()` 的 `now()` 起算；不依赖清理器，不因重试/重启/回退
  续期。`expire()` 只在 `now >= expiresAt` 时移除，并生成新 epoch。
- 配额窗口与活动数由受信配置决定；重复 apply/expire 不重置窗口。
- 进程内状态：重启后发布器不继承 TTL 状态，不能把旧附加规则“恢复”；
  持久化/恢复属于后续（需审计与来源认证）。这会导致保守停止，不是续期。
- 历史上下文无法保证擦除：到期后只保证不新注入/不新评估；旧文本无授权
  效力。

## 4. 与 rollout/安全门的关系

- 本模块不改变 on_hit、不触碰宿主硬拒绝、不越过 rollout 资格。
- 新增限制仍需对应规则的 rollout/证据资格；0 层基线拒绝不可被“更严格”
  叙事替代。
- 任何实际启用还需要预授权、配额/TTL 治理值与审计；默认视为未授予。
