# ADR：来源认证、秘密存储与引导（O5）

- 状态：**草案，pending-human-review**。未实现、未启用、未声称已认证。
- 范围：为未来的规则/激活快照发布来源提供机制选择与威胁假设；不改变当前
  Stage A log-only 或离线编译语义。
- 关联：RULE-11/RULE-13、HOST-01/09、GOV-01/03/09、AC-03/09/11/20；
  PRD §10 O5；`docs/security-model.md`。

## 1. 问题

当前 `activation/` 的 `verify()` 只做**重编译一致性**：它能发现混投影、
伪造 digest 或内容不一致，但无法证明快照来自受信发布者。摘要、`0600`、
同 UID、SQLite 文件权限、插件开关都不是来源认证。治理层发布也必须回答：

- 宿主如何确认“这个 activation snapshot 由已授权发布者产生且未被替换”？
- 秘密材料放在哪里，配置库如何只保存引用？
- 首次引导如何避免把“能写文件”误当成“已授权”？

## 2. 威胁假设

在机制未定前，按以下假设做保守设计：

1. **T1 同 UID Agent 可写**：Agent 与治理/审计文件可能同 UID；仅靠文件
   模式、目录位置或 SQLite 事务不能阻止 Agent 改写策略/审计/快照。
2. **T2 摘要可重算**：任何未带密钥的 digest 都可被有写权限者重算；
   digest 只证明内容一致，不证明来源。
3. **T3 启动配置可被替换**：工作区内的 `.pi/amos.json`、`opencode.jsonc`、
   `constraints/rules.yaml` 都在 Agent 可写域内；不能作为信任根。
4. **T4 重放/降级**：旧但摘要有效的快照、旧 epoch、被撤销授权、回退时钟
   都可能被重放。
5. **T5 秘密外泄**：错误消息、日志、异常、测试工件、备份和 GUI 响应都
   可能携带秘密或原始内容。
6. **T6 供应链/宿主**：宿主二进制、插件加载路径、provider SDK 和 CI 身份
   都可能被替换；本轮没有远程证明能力。

## 3. 候选机制（未选定）

| 机制 | 能证明 | 不能证明 | 结论 |
|---|---|---|---|
| 内容 digest + 重编译 verify | 内容与编译器一致 | 发布者身份、抗替换 | 仅一致性，不是认证；保留 |
| HMAC（进程/部署密钥） | 持有同一密钥者产生 | 密钥与 Agent 同域时仍可伪造；重启/轮换语义 | 候选，需密钥域分离 |
| 非对称签名（发布者私钥） | 对应公钥的签名者产生 | 公钥引导、撤销、宿主时钟 | 候选，需引导 ADR |
| 独立 UID/挂载域/受信服务 | 写域分离带来的强制 | 内核/部署配置错误、宿主被攻破 | 目标方向；本轮未实现 |
| 外部审计锚定/透明日志 | 历史未被单点重写 | 锚定服务自身与可用性 | 后续部署能力 |

**当前决定（保守）**：不实现任何“已认证来源”声明。治理发布只产生
catalog v2 snapshot 并记录编译器/摘要/审计；宿主接收仍要求未来的独立
信任机制。未选定机制前，所有发布/接收状态标 `pending-human-review`，
不得把 digest、HMAC、SQLite 或同 UID 权限描述为认证或隔离。

## 4. 若未来采用签名的最小约束

1. 私钥只在独立秘密存储/受信服务中；配置库只存 `{env:NAME}` 或
   `secret://name` 引用，不存值。
2. 签名覆盖：format/version/compilerVersion、catalogVersion、schemaDigest、
   project identity、active rule refs、epoch、activationDigest、
   snapshot digest、发布者 id、发布时间、nonce。
3. 宿主验证顺序：结构/版本 → 编译一致性 → 签名 → 公钥/撤销 → epoch/
   TTL/时钟 → 能力闭集；任一失败保持停止，不回退旧快照。
4. 密钥轮换/撤销必须有版本与生效时间；旧签名在撤销后不得续用。
5. 引导：公钥或信任根不能放在 Agent 可写的工作区；需要人治理的安装步骤
   与可复核指纹。没有该步骤时标 `unmanaged`。
6. 签名失败、缺公钥、时钟异常、撤销不明都可能阻止启动；不得自动放行。

## 5. 秘密存储

- 配置库/审计/日志只保存引用名；测试与文档不得包含字面凭据。
- 现有 `decision/jev.local.json` 是 Git-ignored 的本地凭据文件；它不是
  受保护秘密存储，也不因 `0600` 成为认证边界。
- 任何新 provider 只接受环境变量名或秘密引用；错误/响应不回显值。
- 备份包含配置与审计时不得包含秘密材料；恢复不因缺秘密而放宽策略。
